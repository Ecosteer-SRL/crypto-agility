====================================================
test_cipher_provider
====================================================

Purpose:
test_cipher_provider verifies that a runtime-loadable cipher provider complies
with the crypto-agility framework ABI and lifecycle contract.

Logic:
The tool:
 1) Parses the arguments and provider confstring.
 2) Loads the provider shared library with dlopen().
 3) Resolves dvco_cipher_provider_get_api() with dlsym().
 4) Checks the mandatory provider functions.
 5) Reads and prints the provider metadata.
 6) Exercises create, reset, rotate, serialization, deserialization,
    comparison, encryption, decryption, and destruction.
 7) Selects the symmetric or asymmetric test path from category_flags.
 8) Verifies the final operation result.

When --aad is supplied, the same Additional Authenticated Data is passed to
encryption and decryption.

Command:
./test_cipher_provider \
  --lib <provider_shared_library> \
  [--confstring "<provider_configuration>"] \
  [--plain "<plaintext>"] \
  [--aad "<text>"]

Arguments:
--lib <path>
  Provider shared library.

--confstring "<string>"
  Optional provider configuration passed to create().
  If omitted, an empty configuration is used.

--plain "<text>"
  Optional plaintext.
  Default: "hello dvco".

--aad "<text>"
  Optional Additional Authenticated Data used for both encryption and
  decryption.

--help
-h
  Print usage information.

Example:
../../build/debug/bin/test_cipher_provider \
  --lib ../../build/debug/lib/libchacha20_poly1305_provider.so \
  --confstring "" \
  --plain "hello dvco" \
  --aad "product-123"


====================================================
bench_cipher_provider
====================================================

Purpose:
bench_cipher_provider measures cipher-provider performance through the
crypto-agility framework ABI.

Logic:
The tool:
 1) Parses the arguments and provider confstring.
 2) Creates deterministic plaintext of the requested size.
 3) Loads the provider and reads its metadata.
 4) Prepares the category-specific encryption and decryption contexts.
 5) Runs a correctness roundtrip.
 6) Measures encryption throughput.
 7) Measures decryption using one of these modes:

    reuse
      Create and initialize one decrypt context, then decrypt N times.

    cycle
      Create, initialize, decrypt, and destroy the context on every iteration.

 8) Prints timings, operations per second, and MiB/s.

When --aad is supplied, the same Additional Authenticated Data is used by the
correctness check and by every timed encryption and decryption operation.
MiB/s is calculated from payload bytes; AAD processing time is included.

Command:
./bench_cipher_provider \
  --cipher <provider_shared_library> \
  [--confstring "<provider_configuration>"] \
  [--aad "<text>"] \
  [--size <bytes>] \
  [--iters <n>] \
  [--decrypt-mode <reuse|cycle>]

Arguments:
--cipher <path>
  Provider shared library.

--lib <path>
  Alias for --cipher.

--confstring "<string>"
  Optional provider configuration passed to create().
  If omitted, an empty configuration is used.

--aad "<text>"
  Optional Additional Authenticated Data used for encryption and decryption.

--size <bytes>
  Plaintext size.
  Default: 1024.

--iters <n>
  Number of iterations.
  Default: 100000.

--decrypt-mode <reuse|cycle>
  Decryption benchmark mode.
  Default: reuse.

--help
-h
  Print usage information.

Example:
../../build/release/bin/bench_cipher_provider \
  --cipher ../../build/release/lib/libchacha20_poly1305_provider.so \
  --confstring "" \
  --aad "product-123" \
  --size 1024 \
  --iters 100000 \
  --decrypt-mode cycle


====================================================
probe_cipher_provider
====================================================

Purpose:
probe_cipher_provider prints provider inputs, serialized material, ciphertext,
decrypted output, and roundtrip evidence.

Use it to inspect provider behavior, compare implementations, and validate
Linux/MCU interoperability before involving the complete application stack.

Logic:
The tool:
 1) Parses the arguments and provider confstring.
 2) Loads the provider and reads its metadata.
 3) Creates the encryption context.
 4) Uses material supplied through the confstring, when present.
 5) Calls rotate() when no usable material is supplied.
 6) Applies caller-side padding when required by provider metadata.
 7) Serializes and prints the shareable material.
 8) Encrypts the plaintext.
 9) Imports the shareable material into a second context.
10) Decrypts and removes caller-side padding when required.
11) Verifies the roundtrip.
12) Prints text, hexadecimal, and Base64 evidence.

When --aad is supplied, the same Additional Authenticated Data is passed to
encryption and decryption. The AAD is also printed as text, hexadecimal,
Base64, and summary.aad_hex.

Command:
./probe_cipher_provider \
  --lib <provider_shared_library> \
  [--confstring "<provider_configuration>"] \
  [--plain "<plaintext>"] \
  [--aad "<text>"]

Arguments:
--lib <path>
  Provider shared library.

--confstring "<string>"
  Optional provider configuration.
  When omitted or empty, the tool generates provider material through rotate().

--plain "<text>"
  Optional plaintext.
  Default: "hello dvco".

--aad "<text>"
  Optional Additional Authenticated Data used for encryption and decryption.

--help
-h
  Print usage information.

Example:
../../build/debug/bin/probe_cipher_provider \
  --lib ../../build/debug/lib/libchacha20_poly1305_provider.so \
  --plain "hello dvco running on psoc" \
  --aad "aadangraz"

Relationship With Other Tools:
test_cipher_provider verifies the provider contract.
bench_cipher_provider measures provider performance.
probe_cipher_provider shows what the provider produces.

In short:
  test  = is the provider contract correct?
  bench = how fast is the provider?
  probe = what exactly does the provider produce?
