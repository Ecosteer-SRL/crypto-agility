====================================================
test_cipher_provider
====================================================

Purpose:
test_cipher_provider is a standalone compliance test tool for cipher providers
compliant with the crypto-agility framework.
Its objective is to verify whether a cipher-provider implementation exposes and
exercises the complete mandatory vtable defined by the cipher-provider framework.
To do this, the program loads a provider shared library at runtime, resolves the
provider API, obtains the vtable, checks that all required functions are available
and callable, reads the provider metadata, and selects the appropriate test path
based on the provider category.
It then exercises the provider lifecycle through the vtable to confirm that the
implementation behaves consistently with the framework contract.

Compliance Logic:
The program checks compliance by loading the provider dynamically, verifying that
the provider exposes the expected ABI entry point and mandatory vtable functions,
and reading the provider metadata returned by get_info().
The metadata includes category_flags, which tells the tool whether the provider
must be exercised as a symmetric provider, an asymmetric provider, or another
supported provider category.

The main sequence is:
 1) Parse command-line arguments and confstring.
 2) Load the provider .so with dlopen().
 3) Resolve dvco_cipher_provider_get_api with dlsym().
 4) Call dvco_cipher_provider_get_api() to obtain the provider vtable.
 5) Check that all mandatory vtable functions are present:
    get_info, create, destroy, reset, rotate,
    serialize_shareable, deserialize_shareable,
    serialize_private, deserialize_private,
    compare_shareable, compare_private,
    encrypt, decrypt, last_error.
 6) Call get_info() and print provider metadata, including category_flags.
 7) Call create() to create the first provider context.
 8) Call reset() on the first provider context.
 9) Call rotate() to generate or activate provider material.
10) Call serialize_shareable().
11) Call serialize_private().
12) Create one or more additional provider contexts as required by the
    provider category.
13) Call deserialize_shareable() and deserialize_private() as required by
    the selected category-specific test path.
14) Call compare_shareable().
15) Call compare_private().
16) Exercise the provider operation path selected according to category_flags.
    For symmetric providers, this is the encrypt/decrypt roundtrip path.
    For asymmetric providers, this is the asymmetric operation path implemented
    by the tool.
17) Verify that the produced result is consistent with the expected result for
    the selected provider category.
18) Destroy all contexts and close the provider library.

Command:
./test_cipher_provider \
  --lib <provider_shared_library> \
  [--confstring "<provider_configuration>"] \
  [--plain "<plaintext>"]

Arguments:
--lib <path>
  Path to the runtime-loadable cipher-provider shared library to be tested.
--confstring "<string>"
  Optional provider-specific configuration string.
  The string is parsed by the tool and passed to the provider create() function.
  If omitted, an empty configuration string is used.
--plain "<text>"
  Optional plaintext used for the category-specific correctness test.
  If omitted, the default plaintext is "hello dvco".
--help
-h
  Print usage information.

Example:
../../build/debug/bin/test_cipher_provider \
  --lib ../../build/debug/lib/libaes_gcm_provider.so \
  --confstring "" \
  --plain "hello dvco"


====================================================
bench_cipher_provider
====================================================

Purpose:
bench_cipher_provider is a standalone benchmark tool for cipher providers.
It measures provider throughput when a cipher-provider implementation is exercised
through the cipher-provider framework ABI.
The program loads a provider shared library at runtime, resolves the provider API,
obtains the vtable, prepares deterministic input data, verifies that the provider
can complete the category-specific correctness path, and then measures the
corresponding provider operation throughput.
The tool is provider-neutral: it does not benchmark a raw cryptographic primitive
directly, but the provider execution path through the framework vtable ABI.

Benchmark Logic:
The program benchmarks a provider by first executing a category-specific
correctness setup phase and then running the benchmark phases supported for that
provider category.
The provider category is read from category_flags returned by get_info().

The main sequence is:
 1) Parse command-line arguments and confstring.
 2) Allocate a deterministic input buffer of the requested size.
 3) Fill the input buffer using:
    input[i] = (uint8_t)(i & 0xff)
 4) Load the provider .so with dlopen().
 5) Resolve dvco_cipher_provider_get_api with dlsym().
 6) Call dvco_cipher_provider_get_api() to obtain the provider vtable.
 7) Check that the required benchmark vtable functions are present:
    get_info, create, destroy, rotate,
    serialize_shareable, deserialize_shareable,
    encrypt, decrypt.
 8) Call get_info() and read provider metadata, including category_flags.
 9) Select the benchmark path according to category_flags.
10) For symmetric providers, prepare an encryption input, applying caller-side
    padding if the provider metadata requires it.
11) For symmetric providers, run a correctness encrypt/decrypt roundtrip before
    benchmarking.
12) For asymmetric providers, run the asymmetric correctness path implemented
    by the tool before benchmarking.
13) Abort the benchmark if the correctness check fails.
14) Run the benchmark operation path selected according to category_flags.
15) For symmetric providers, run the encryption benchmark.
16) For symmetric providers, run the decrypt benchmark according to
    --decrypt-mode:
    reuse:
      create a decrypt context once
      deserialize_shareable into the decrypt context once
      repeat N times:
        decrypt the immutable reference ciphertext
      destroy the decrypt context
    cycle:
      repeat N times:
        create a fresh decrypt context
        deserialize_shareable into the decrypt context
        decrypt the immutable reference ciphertext
        destroy the decrypt context
17) For asymmetric providers, run the asymmetric benchmark path implemented by
    the tool.
18) Print provider metadata, category_flags, payload sizes, selected benchmark
    mode, timings, operations per second, and MiB/s results where applicable.
19) Destroy contexts, close the provider library, and release allocated buffers.

Command:
./bench_cipher_provider \
  --cipher <provider_shared_library> \
  [--confstring "<provider_configuration>"] \
  [--size <bytes>] \
  [--iters <n>] \
  [--decrypt-mode <reuse|cycle>]

Arguments:
--cipher <path>
  Path to the runtime-loadable cipher-provider shared library to be benchmarked.
--lib <path>
  Alias for --cipher.
--confstring "<string>"
  Optional provider-specific configuration string.
  The string is parsed by the tool and passed to the provider create() function.
  If omitted, an empty configuration string is used.
--size <bytes>
  Optional input payload size in bytes.
  If omitted, the default size is 1024 bytes.
--iters <n>
  Optional number of benchmark iterations.
  If omitted, the default number of iterations is 100000.
--decrypt-mode <reuse|cycle>
  Optional decrypt benchmark mode used by symmetric-provider benchmarks.
  reuse creates one decrypt context, imports shareable material once, and repeats decrypt N times.
  cycle creates a fresh decrypt context, imports shareable material, decrypts once, and
  destroys the context for each iteration.
  If omitted, reuse is used.
--help
-h
  Print usage information.

Example:
../../build/release/bin/bench_cipher_provider \
  --cipher ../../build/release/lib/libaes_gcm_provider.so \
  --confstring "" \
  --size 1024 \
  --iters 100000 \
  --decrypt-mode reuse
